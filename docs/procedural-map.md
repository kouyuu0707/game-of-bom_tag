# 自動生成マップ

シングルと協力モードで同じマップ生成を使います。
壁・広場・通路と、鬼・補充アイテムの配置を、Map番号からルールに従って生成します。
外部の生成AIサービス、APIキー、追加の利用料は不要です。

## 更新して試す

1. 再生と古いexeを終了し、Windows側の変更を保存して `feature/bomb-inventory` をPullします。
2. Unityのコンパイル完了後、`Tools → Bomb Tag → Create or Open Online Test` を選びます。
   GroundにProceduralArenaを追加し、壁のマテリアルを接続します。既存のシーン配置は維持します。
3. ▶からSingle Playerを選ぶと、新しいマップで開始します。
4. ゲーム終了後の **Retry** は、同じ壁・鬼・補充配置でやり直します。
5. **New map** は、別のMap番号で配置を作り直し、そのまま開始します。
6. 協力プレイは両方のビルドを最新版にして2人接続し、ホストがStart gameを押します。
   RetryとNew mapもホストが操作します。

今回は通信する状態の構成が変わるため、古いexeとは接続できないようプロトコルのバージョンも更新しています。
友達へは `Build Windows Connection Test` で作り直した出力フォルダー全体を渡してください。

## 配置と同期

- 15×15マス、1マス3ユニット。既存の50×50の地面内に収めます。
- 外周を壁で囲み、開始地点の周囲5×5マスを広場として確保します。
- 内部の壁は最大40マス。壁を追加するたびに、全通路がつながっているか確認します。
- 通路の幅は1マス＝3ユニットあり、プレイヤーと鬼が通れます。
- プレイヤー2か所、鬼2体、補充アイテム8個の位置は、壁と重ならない別々のマスに置きます。
- 鬼は開始広場の外に配置します。全ての出現位置は同じ歩行可能エリアにつながります。
- ホストがMap番号を決定し、各端末が同じ整数演算で同じ壁を作ります。
- 開始前にホストがNavMeshを作り、全ての出現位置へ経路があることもUnity側で確認します。
  NavMeshを生成できない場合は開始せず、画面に理由を表示します。
- RetryはMap番号を変えません。New mapと新しい部屋は新しい配置になります。
- 古い壁はすぐ無効化してから削除し、前のマップの衝突が残らないようにしています。

今までのOnlineRoundプレハブにあったEnemy Positions／Pickup Positionsの固定配置は使わず、
MapGeneratorが配置を決めます。生成する鬼は2体、補充アイテムは8個です。

## 壁と攻撃

生成された壁はプレイヤーを止め、鬼はNavMeshで回り道します。
爆風、鬼との接触ダメージ、アイテム取得は、壁を隔てた相手には届きません。
爆発の輪も、壁に当たる位置で短く表示します。爆弾の誘爆や壁の破壊は未実装です。
手作業で追加した壁も攻撃を遮るようにしたい場合は、ColliderとGeneratedWallを付け、Groundの子に配置してください。

## Unityでの確認

- 開始地点の広場と、周囲の壁・通路が表示され、壁をすり抜けない。
- 鬼が壁をすり抜けず、通路を通って追跡してくる。
- 鬼・補充アイテムが壁の中に現れず、通路から到達できる。
- 壁の向こうで起爆してもHPが減らず、鬼も倒れない。通路で起爆した場合は当たる。
- 壁の角越しに鬼に触れたり、アイテムを拾ったりできない。
- Retry後もMap番号と全配置が同じで、HP・残弾・鬼・補充だけ初期化される。
- New mapでMap番号と配置が変わり、以前の壁や爆弾が残らない。
- 協力プレイで両画面のMap番号・壁・鬼・補充の配置が一致する。
- 切断して新しい部屋を作った場合も、前のマップが残らない。
- Consoleに赤いエラーが出ない。

## 検証結果

マップ関連7件を含む、Unity非依存のルールテスト32件を.NETで実行して全件成功しました。
1000個のMap番号について全ての通路がつながること、500個について出現位置が重ならないことを確認しています。
同じ番号の再現性、異なる番号での変化、開始広場・外周・地面内への収まりも確認しています。

UnityのTest Runnerでは合計43件を実行できます（今回追加した壁の物理判定3件を含む）。
クラウドではUnityでのコンパイル・NavMesh生成・物理判定・2画面通信は未検証です。
上記のUnityでの確認を別途行ってください。
